## Decisions & Alternatives Considered
- **Skip JIRA PUT on repair vs force PUT:** Skipping avoids 400 from JIRA when version already released (immutable date) and keeps repair idempotent; alternative (re-PUT with same releaseDate) risks JIRA validation errors — rejected.
- **Detect via synced + live:** `_jira.released` (persisted from prior sync) covers offline/cached case; live `getProjectVersions` covers out-of-band JIRA release — both ORed into `jiraAlreadyReleased`.
- **Keep 409 for lighthouse-already-released:** Prevents double email / double ticket-move; repair only applies when `existing.released` is true? Actually check is `existing.released` → 409, so repair only when lighthouse NOT released but JIRA is — intentional to avoid re-moving already-master tickets.
